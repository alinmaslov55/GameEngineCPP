[P0] CRITICAL CORRECTNESS BUGS & CONCURRENCY HAZARDS

[x] 1. Fix Exponential MassMultiplier Runaway & Remove Per-Frame RegisterRuntimeBody Polling
    - Files: Engine/src/Scene/Scene.cpp (lines 427-431, 1646-1650), Engine/include/Engine/Physics/PhysicsComponents.h
    - Root Cause:
      * Scene::UpdateRuntime() calls RegisterRuntimeBody(go.get()) on every active GameObject every frame.
      * Inside RegisterRuntimeBody(), `massData.mass *= rb2d->MassMultiplier` compounds exponentially each frame (e.g., MassMultiplier = 2.0f becomes 2^60 after 60 frames -> Inf/NaN), and resets Box2D body damping/bullet flags redundantly every tick.
    - Solution:
      * Store unscaled base mass / inertia (or track m_AppliedMassMultiplier) so SetMassMultiplier() scales idempotently against base shape mass.
      * Replace full-scene RegisterRuntimeBody() polling in UpdateRuntime() with a Physics Dirty-Flag / PendingSync set populated on AddComponent, RemoveComponent, or property setters.
    - Verification (EngineTests): Step a Rigidbody2D with MassMultiplier = 2.5f and LinearDamping = 3.0f for 120 frames; assert GetMass() stays constant and velocity decays identically.

[x] 2. Fix Same-Frame Spawn-Then-Destroy Use-After-Free in FlushEntityLifecycleQueues()
    - Files: Engine/src/Scene/Scene.cpp (lines 149-193, 1105-1161)
    - Root Cause:
      * If entity A (and optionally child B) is created while m_IsIteratingEntities == true (held in m_PendingSpawnQueue) and destroyed in the same frame via DestroyGameObject(), it gets pushed into m_PendingDestroyQueue as well.
      * FlushEntityLifecycleQueues() Loop 1 calls OnDestroy() and clears m_PendingSpawnQueue (freeing heap memory), then Loop 2 iterates m_PendingDestroyQueue and dereferences the freed pointer (Use-After-Free + double OnDestroy()).
    - Solution:
      * Track explicit lifecycle state enum (PendingSpawn, Alive, PendingDestroy, Destroyed) on GameObject.
      * Only append Alive entities to m_PendingDestroyQueue; entities in PendingSpawn only get marked m_PendingDestroy = true and torn down once during Pass 1.
    - Verification (EngineTests): Spawn parent+child hierarchy inside Component::Update(), destroy parent in the same Update() call, run under AddressSanitizer / MSVC CRT heap check -> zero UAF and OnDestroy() count == 1.

[x] 3. Add Iteration Guard & Flush Around FixedUpdate + Convert Flag to Reentrant Counter
    - Files: Engine/src/Scene/Scene.cpp (lines 1166-1175, 1673-1678, 1835-2039), Engine/include/Engine/Scene/Scene.h
    - Root Cause:
      * Scene::UpdateRuntime() invokes go->FixedUpdate(fixedDt) without setting m_IsIteratingEntities = true or flushing queues afterward, allowing mid-loop m_GameObjects vector mutation/UB if FixedUpdate() spawns or destroys entities.
      * Nested loops manually toggling `bool m_IsIteratingEntities` can reset the outer scope's flag prematurely.
    - Solution:
      * Replace `bool m_IsIteratingEntities` with `uint32_t m_IterationDepth` + RAII `ScopedIterationGuard` wrapping Update(), FixedUpdate(), and ProcessPhysicsEvents(), auto-flushing queues when depth returns to 0.
    - Verification (EngineTests): Spawn and destroy pooled/runtime entities inside Component::FixedUpdate() across 30 frames with zero skipped iterations or crashes.

[x] 4. Fix GameObject::m_Components Loop Reallocation UB & Vector Shifting Skips
    - Files: Engine/include/Engine/Scene/GameObject.h (lines 117-203), Engine/src/Scene/GameObject.cpp (lines 19-53)
    - Root Cause:
      * Update(), FixedUpdate(), LateUpdate(), ProcessPendingStarts(), and NotifyHierarchyActiveChanged() use range-based for loops over m_Components. Calling AddComponent<T>() or RemoveComponent<T>() on `this` inside Start()/Update()/OnCollisionEnter2D() invalidates iterators or skips shifted indices.
      * DispatchCollision*/DispatchTrigger* checks IsActiveInHierarchy() only at entry, not if an earlier component disables or destroys the owner mid-dispatch.
    - Solution:
      * Iterate using index-based loops checking `i < m_Components.size()` and `IsActiveInHierarchy()` (or small-buffer deferred component removal queue).
    - Verification (EngineTests): Component A adds Component B and removes itself during Update() and OnCollisionEnter2D(); verify B runs cleanly with zero iterator invalidation.

[ ] 5. Fix Data Race on Transform::m_CachedWorldMatrix in DrawStandeesParallel & Thread-Safe UUIDs
    - Files: Engine/src/Renderer/Renderer2D.cpp (lines 744-757), Engine/include/Engine/Scene/Transform.h, Engine/src/Scene/Transform.cpp, Engine/src/Scene/Object.cpp (lines 6-11), Engine/src/Scene/Scene.cpp (line 2287)
    - Root Cause:
      * DrawStandeesParallel runs on JobSystem worker threads and calls cmd.transform->GetWorldPosition() / GetWorldRotation(). Transform::GetWorldMatrix() mutates unsynchronized `mutable` fields (`m_WorldDirty`, `m_CachedWorldMatrix`, `m_LastPosition`). Parented standees trigger concurrent read/write races on worker threads.
      * Object.cpp::GenerateUUID() uses shared static `std::mt19937_64` without locking.
    - Solution:
      * Precompute `worldPosition` (interpolated via `m_PhysicsAlpha` to complete ECS-02 visual smoothing!) and `worldRotation` once on the main thread inside Scene::GatherRenderContext() into StandeeRenderCommand.
      * Mark DrawStandeesParallel read-only against POD command fields; change `GenerateUUID()` RNG to `thread_local std::mt19937_64`.
    - Verification (EngineTests): Render parented hierarchical standees across multi-threaded JobSystem with ThreadSanitizer/concurrent stress test -> zero data races and smooth sub-frame alpha interpolation.

[ ] 6. Fix Missed-Wakeup Race & False Sharing in JobSystem
    - Files: Engine/include/Engine/Core/JobSystem.h, Engine/src/Core/JobSystem.cpp (lines 204-295), Engine/include/Engine/Scene/Scene.h (line 136)
    - Root Cause:
      * SubmitJob() calls `m_WakeCV.notify_one()` WITHOUT holding `m_WakeMutex`, while WorkerLoop evaluates `HasPendingWork()` scanning N worker queue mutexes sequentially inside cv.wait(). A notification occurring after HasPendingWork() checked queue[0] and before kernel park can be lost, stranding workers.
      * Scene::Box2DTask (16 bytes) and JobSystem::WorkerQueue lack cache-line alignment, causing false sharing across atomic counters.
    - Solution:
      * Maintain `std::atomic<size_t> m_PendingJobs{0}` (plus `m_WaitingWorkers` atomic counter) and acquire `m_WakeMutex` around notification when waiters exist, eliminating lock-per-queue scanning and lost wakeups.
      * Apply `alignas(64)` to `Box2DTask` and `WorkerQueue`.
    - Verification (EngineTests): High-frequency single-job producer-consumer stress test (100k micro-dispatches with 1-8 workers) completes reliably with zero hangs.

[ ] 7. Fix Chronos Stasis Initialization on OnRuntimeStart & Non-Runtime Fallback Bugs

    - Root Cause:

    - Verification (EngineTests): Deserialize a stasis-frozen enemy, call OnRuntimeStart(), step 60 frames -> remains suspended; run PhysicsQueries unit tests in both runtime and non-runtime modes.

[P2] HOT-PATH DATA-ORIENTED OPTIMIZATIONS & ALLOCATION REMOVAL

[ ] 12. Eliminate RTTI dynamic_cast in GameObject::GetComponent<T>()
    - Files: Engine/include/Engine/Scene/Component.h, Engine/include/Engine/Scene/GameObject.h (lines 40-48, 205-237)
    - Root Cause:
      * Whenever `ComponentMask128` bit matches, `GetComponent<T>()` and `GetComponents<T>()` perform a linear scan executing slow C++ RTTI `dynamic_cast<T*>()` per component. Hot paths invoke this tens of thousands of times per second.
    - Solution:
      * Cache `uint16_t m_TypeId` on each Component during `AddComponent<T>()`.
      * In `GetComponent<T>()`, compare `comp->GetTypeID() == Detail::GetComponentTypeID<T>()` cleanly for exact types (falling back to `dynamic_cast` only for base-class polymorphic queries via `std::is_final_v` or an `exact_match` vs `base` fast path, or storing base mask).
    - Expected Impact: Eliminates RTTI string/typeinfo tree traversal on all hot component lookups.

[ ] 13. Maintain Dense Contiguous Physics Registry & Sync Only Moved Bodies via b2World_GetBodyEvents
    - Files: Engine/src/Scene/Scene.cpp (lines 1663-1798)
    - Root Cause:
      * Each physics substep (up to 6x/frame) loops over ALL `m_GameObjects` (including hundreds of static grass tufts, trees, and inactive UI objects) 5 separate times: PreviousSnapshot, FixedUpdate, Pre-Step Airborne Check, Post-Step Box2D Sync, and IntegrateVerticalElevation (including duplicate Airborne Check!).
    - Solution:
      * Maintain a dense contiguous `std::vector<PhysicsBodyEntry>` (`{GameObject*, Transform*, Rigidbody2D*, b2BodyId}`) inside `PhysicsWorld2D` so physics never iterates non-physics entities or sleeping static props.
      * Replace Pass 4 full-entity Box2D->Transform loop with Box2D v3's `b2World_GetBodyEvents(worldId)` (`moveEvents`), syncing transforms in O(actually moved dynamic bodies).
      * Deduplicate the Airborne Pass-Through check (run once right after `IntegrateVerticalElevation` + handle mid-air `SetMaskBits` calls respecting `IsAirbornePassThroughActive()`).
      * Optional: Parallelize pure math vertical integration across dense entries via `JobSystem::ParallelForBatched` (collecting only threshold-crossing entities for main-thread `b2Shape_SetFilter`).
    - Expected Impact: 5x-15x faster physics sync & elevation step on cluttered diorama scenes with 300+ standees.

[ ] 14. Eliminate Per-Step & Per-Query Dynamic Heap Allocations (Zero-Allocation Hot Paths)
    - Files: Engine/src/Scene/Scene.cpp (lines 1831-1915), Engine/src/Physics/PhysicsQueries.cpp (lines 17-37, 41-141), Engine/include/Engine/Core/JobSystem.h (lines 114-185)
    - Details:

      * `PhysicsQueries::OverlapCircleXZ()`: Replace per-call `std::unordered_set<GameObject*>` inside `OverlapContext` with O(1) linear dedup for small N (`<= 32`, stack-allocated small buffer / `outHits` scan) or a reusable query stamp array/scratch set.
